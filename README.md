# 株式会社NFTDrive 公式デコーダー（PHP）

Symbol ブロックチェーン上の NFTDrive レコードを取得・復元し、元のファイルとして返す
PHP 製デコーダーです。

> **これらのデコーダーは、NFTDrive の記録を読むための標準的な実装サンプルです。**
> 動作・安全性・可用性は保証しません。設置・公開する方は、下の
> [注意事項](#注意事項設置する前に必ず読んでください)を読み、必要に応じて自分で修正してください。

自由に利用・改編できます。このプログラムを含むデコーダーを公開する場合は、
[利用規約](https://nft-drive.localinfo.jp/posts/23874701)を確認してください。

[株式会社NFTDrive](https://nftdrive.net)

---

## どちらを使うか

| ファイル | 対象 | 使う場面 |
|---|---|---|
| [`download-v3.php`](./download-v3.php) | **BEYOND / NFTDrive-v3 対応版** | 新しく設置するならこちら。BEYOND で記録したデータも読める |
| [`download.php`](./download.php) | 従来版 | すでに設置していて、挙動を変えたくない場合。従来の形式（Base64・平文）だけを読む |

`download-v3.php` は `download.php` を元にしており、**従来の形式の返し方は同じ**です。
置き換えるときは、ファイル名を `download.php` に変えて上書きすれば、呼び出し側の URL を変えずに済みます。

## 従来版との違い

### 保存形式ごとの返り

どちらも同じレコードを通して確かめた結果です。

| レコードの形式 | 従来版 `download.php` | v3 対応版 `download-v3.php` |
|---|---|---|
| Base64・平文（`data:…`） | ✅ 元のファイル | ✅ 元のファイル（同じ） |
| **バイナリ・平文**（`nftdrive;binary/<MIME>`） | ❌ `text/plain` で壊れた中身。先頭にヘッダー文字列、チャンクごとに `0x00` が混ざる | ✅ 元のファイル。MIME はスロット15から |
| **暗号化・Base64**（`BYNDE1.…`） | △ `text/plain` で暗号文。ただし先頭とチャンクの間に `0x00` が混ざる | ✅ `text/plain` で暗号文そのまま |
| **暗号化・旧形式**（`U2FsdGVkX1…`） | △ 同上（`0x00` が混ざる） | ✅ `text/plain` で暗号文そのまま |
| **暗号化・バイナリ**（`nftdrive;binary/encrypted;<MIME>`） | ❌ `text/plain` で壊れた中身 | ✅ 封筒そのまま。BYNDB1 は `application/octet-stream`、古い記録の BYNDE1 は `text/plain` |
| 判別できない形式 | △ `text/plain`（`0x00` が混ざる） | △ `text/plain`（中身そのまま） |
| **ブロックが欠けている** | ❌ 欠けたまま `200` で返す | ✅ `503` で断り、欠けたブロック番号を返す |

### 機能の違い

| 項目 | 従来版 | v3 対応版 |
|---|---|---|
| 保存形式の判別 | しない（`base64` という文字を含むかだけ見る） | ブロック0スロット15で判別 |
| メッセージ先頭の `0x00` | 残したままつなぐ | 落としてからつなぐ |
| 返した形式の通知 | なし | `X-NFTDrive-Format` ヘッダー（[レスポンス](#レスポンスv3-対応版)） |
| 暗号化データの元の MIME | 分からない | 暗号化バイナリは `X-NFTDrive-Mime` で返す |
| 欠けの検出 | なし | あり（`503`） |
| 復号 | しない | しない（[暗号化データについて](#暗号化データについて)） |
| ノードの書き方 | ホスト名だけ（`http://<ホスト>:3000`） | ホスト名、または `https://host:3001` のような完全な URL |
| testnet のノード一覧 | 古い一覧（`test02.xymnodes.com` など） | 現行の6ノード |
| ブラックリストが取れないとき | 処理ごと止まる（PHP 8 で `count(null)` が TypeError） | 確かめずに処理を続ける |
| MIME ごとの扱い（glb・bvh・ATNFT・ジェネラティブ・特定ホストの動画ラッパー） | あり | 同じ（手を付けていない） |
| 注意事項の SSRF など | 未対処 | 未対処（同じ。[注意事項](#注意事項設置する前に必ず読んでください)） |

## 設置

使うファイル（`download-v3.php` か `download.php`）を、PHP が動く Web サーバー
（Apache・XAMPP など）に置きます。

| 必要なもの | 用途 |
|---|---|
| PHP 8.x | v3 対応版は PHP 8.2 で確認。7.x でも動く見込みですが確認していません |
| 拡張 `curl` | ノードへの問い合わせ |
| 拡張 `fileinfo` | ATNFT（URL を指すレコード）の MIME 判定 |
| 拡張 `gd` | ジェネラティブ画像の合成 |

### ノードの設定

ファイル先頭の `$node_list` に、使うノードを書きます。

```php
$node_list = [
  "example-node1.com",              // ホスト名だけなら http://<ホスト>:3000
  "https://example-node2.net:3001"  // 完全な URL（v3 対応版のみ）
];
```

- mainnet は先頭の `$node_list` を使います
- testnet（アドレスが `N` 以外で始まる）は、ファイル中ほどにある testnet 用の一覧を使います
- どちらも、つながらないノードは飛ばして次を試します

### API の最大ページ数

`$restCount` に、ノードの REST API が1ページで返す最大件数を設定します。通常は 100 です。

```php
$restCount = 100;
```

## 使い方

モザイク ID か、データアドレスを渡します。

```
download-v3.php?id={モザイクID}
download-v3.php?address={データアドレス}
```

平文のレコードは、元のファイルをその MIME で返します。`<img src="download-v3.php?address=...">`
のように、そのまま画像や動画として使えます。

## レスポンス（v3 対応版）

形式はブロック0の15番目のスロット（0 始まり）の先頭で決まり、何を返したかを
`X-NFTDrive-Format` ヘッダーで知らせます。

| スロット15の先頭 | `X-NFTDrive-Format` | Content-Type | 本文 |
|---|---|---|---|
| `data:` | `base64` | 元の MIME | 元のファイル |
| `nftdrive;binary/<MIME>` | `binary` | 元の MIME | 元のファイル |
| `BYNDE1.` | `bynde1` | `text/plain` | `BYNDE1.…` の封筒文字列 |
| `U2FsdGVkX1` | `legacy` | `text/plain` | `U2FsdGVkX1…` の暗号文 |
| `nftdrive;binary/encrypted;<MIME>` | `binary-encrypted` | `application/octet-stream`（BYNDB1）/ `text/plain`（BYNDE1） | 封筒そのもの |
| 上記以外 | `unknown` | `text/plain` | つないだ中身 |
| （ブロックの欠け） | `incomplete` | `text/plain`（ステータス 503） | 欠けているブロック番号 |

暗号化バイナリには、さらに次のヘッダーが付きます。

| ヘッダー | 内容 |
|---|---|
| `X-NFTDrive-Envelope` | `BYNDB1` / `BYNDE1` / `unknown` |
| `X-NFTDrive-Mime` | 復号したあとのファイルの MIME |

ブラウザの JavaScript からこれらのヘッダーを読むには、CORS の設定
（`Access-Control-Allow-Origin` と `Access-Control-Expose-Headers`）が要ります。
ファイル中では該当の行をコメントにしてあります。必要なら有効にしてください。

## 暗号化データについて

**どちらのデコーダーも復号しません。** 暗号文をそのまま返し、復号はクライアント側の責任とします。

サーバー側で復号するには、パスワードをサーバーへ送らせる必要があります。
URL に載せればアクセスログにも残ります。それを避けるための設計です。

復号の手順（封筒の構造・Key Slot・AAD）は、NFTDrive の単体ビューア
（[SymbolTransactionFetcher の `sample/`](https://github.com/bootarou/SymbolTransactionFetcher/tree/main/sample)）
が参照実装です。共有パスワード（`password` スロット）があるファイルは、
そのビューアでブラウザ内だけで開けます。

> **復旧フレーズや Address Master Key を入力させる仕組みを作らないでください。**
> 共有パスワードの無いファイルは、BEYOND 本体で開くよう案内してください。

## 注意事項（設置する前に必ず読んでください）

どちらのデコーダーも、チェーン上の**誰でも書けるデータ**をサーバーで処理します。
次の挙動を理解したうえで設置してください。直すかどうかは設置する方の判断に任せます。

### 1. 外部 URL への取得（SSRF）

- **ATNFT:** 復元した中身が `h` で始まり `http` を含むと、サーバーがその URL を
  `file_get_contents()` で取得し、結果を返します。
- **ジェネラティブ画像:** 中身に含まれる文字列を、そのまま `imagecreatefrompng()` に渡します。

チェーンに書いた人が、**あなたのサーバーから任意の URL（社内ネットワークやクラウドのメタデータ
エンドポイントを含む）へアクセスさせる**ことができます。公開サーバーに置くなら、
取得先を `https://` の外部アドレスに限る、あるいはこの処理を外すことを検討してください。

### 2. HTML・スクリプトの配信

`text/html` や `image/svg+xml` のレコードは、**設置したドメインのコンテンツとして**そのまま返します。
中のスクリプトはそのドメインで動きます。ログインなどのある既存サイトとは別の、
専用のドメインで配信してください。

### 3. 一時ファイル

Base64 の中身を、デコーダーと同じディレクトリに一時ファイルとして書き出してから読み戻します。
書き込み権限が要り、処理が途中で止まるとファイルが残ることがあります。

### 4. メモリと時間

レコード全体を PHP の文字列としてメモリに持ちます。大きなファイルは `memory_limit` と
`max_execution_time`（ファイル中で 600 秒に設定）に当たります。v3 対応版のバイナリ保存モードは、
いったん Base64 に直してから従来の処理に渡すので、元のファイルの数倍のメモリを使います。

### 5. ブラックリスト

処理のたびに `https://nftdrive.net/black_list/` を取得し、載っている ID・アドレスは返しません。
取得できなかったとき、従来版は処理ごと止まり、v3 対応版は確かめずに処理を続けます。

### 6. 特定ホストでの挙動

`nftdrive-explorer.info` / `nft-drive` / `nftdrive-ex.net` で動かしたときだけ、
音声・動画をダウンロードさせない HTML で包んで返します。ほかのホストでは元のファイルを返します。

## 仕組み（v3 対応版）

1. データアドレス宛の確定済みトランザクションを全ページ取得する
2. アグリゲートトランザクション（type 16705）ごとに、内部の転送（type 16724）のメッセージを読む
   - スロット0がブロック番号。ブロック0のスロット1〜14はメタデータ
   - 各メッセージの先頭の `0x00` を落として持つ
3. ブロック番号で並べ、欠けが無いことを確かめる
4. スロット15で形式を決め、データ部をつなぐ
   - Base64 保存モード: ブロック0はスロット15から、以降はスロット1から
   - バイナリ保存モード: ブロック0はスロット16から、以降はスロット1から
5. 形式に応じて返す（[レスポンス](#レスポンスv3-対応版)）

保存形式の詳しい仕様は、BEYOND のリポジトリにある `docs/decoder-migration-guide.md`
（デコーダー移行ガイド）と `docs/file-envelope-spec.md`（封筒の仕様）にあります。
